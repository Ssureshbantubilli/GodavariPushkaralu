01 · Project Overview

What This
System Does

The Godavari Pushkaralu AI-ISMS is a real-time crowd safety platform for India's largest religious gathering. The system continuously ingests data from cameras and sensors distributed across all riverbank ghat zones, runs it through a multi-layer AI pipeline, and surfaces actionable alerts to command center operators — all within 3 seconds of a threshold breach.

The prototype (Phase 0 / MVP) runs entirely on a single machine using a simulation engine in place of live cameras, allowing full demonstration of all AI capabilities before the ₹16.8 Crore hardware procurement begins.

System Philosophy

DETECT
Real-Time Awareness

Every 2 seconds, crowd density, person count, and anomaly scores are refreshed for all 10 zones. No polling — operators see changes as they happen via WebSocket push.

DECIDE
AI-Driven Scoring

The SLM engine maps raw crowd readings to a risk score using trained ML models. It factors density, inflow rate, temperature, rain, and historical patterns from Kumbh Mela data.

RESPOND
Actionable Narration

Claude (Anthropic API) auto-generates bilingual incident reports in English and Telugu the moment an alert fires — giving operators human-readable context in under 8 seconds.

03 · Component Reference

What Each
Program Does

app.py

Flask Application

The central web server. Serves the operator dashboard, handles all HTTP requests, and streams real-time data to connected browsers.

  • Serves command center dashboard UI at /
  • REST API endpoints for cameras, alerts, incidents
  • Server-Sent Events (SSE) for live data push to browser
  • Integrates crowd simulator + SLM engine at startup
  • Handles WebSocket connections for live zone updates
  • Incident report endpoint (calls Claude API)
  • Routes: /api/dashboard/summary, /api/alerts, /ws
crowd_simulator.py

Crowd Simulation Engine

Generates realistic, time-varying crowd data for all 10 ghat zones. Replaces live cameras in demo/test mode. Runs as a background thread.

  • Simulates density, inflow/outflow, temperature, rain
  • Models time-of-day peaks (5–8am & 5–7pm)
  • 2% chance/tick of spontaneous surge event per zone
  • Sinusoidal day cycle + Gaussian noise + drift
  • get_all_snapshots() — returns live state dict
  • force_incident(ghat) — triggers RED alert instantly
  • Publishes to SQLite DB + in-memory state every 2.5s
slm_engine.py

AI / SLM Engine

The intelligence core. Loads trained ML models, processes crowd snapshots, and outputs risk scores, alert levels, and response messages.

  • Loads slm_bundle.pkl (sklearn pipeline) at startup
  • Predicts alert level: GREEN / YELLOW / ORANGE / RED
  • Detects anomalies: stampede risk, loitering, surges
  • Generates actionable alert text from templates
  • Scores every zone snapshot — 10 zones × every 2.5s
  • Feeds results to Flask alert dispatcher
  • Configurable thresholds in engine config
data/ · models/

Data & Model Store

Persists all operational data and trained model artifacts. SQLite for development; upgrades to PostgreSQL in production.

  • data/godavari_isms.db — SQLite operational DB
  • data/historical_patterns/ — baseline crowd data
  • data/training_scenarios/ — incident examples
  • models/slm_bundle.pkl — trained ML model
  • models/response_templates.json — alert text
  • Tables: cameras, crowd_readings, alerts, incidents
  • Redis cache layer for real-time zone state
frontend/ · templates/ · static/

Dashboard UI

The operator-facing command center. Built in React 18 with canvas-rendered maps, live camera feeds, and real-time alert panels.

  • Overview: 10-zone status grid + ghat heatmap
  • Ghat Map: Canvas-rendered Godavari river + zones
  • Camera Feeds: 5 simulated feeds with AI bounding boxes
  • Alert Log: Real-time alert stream with resolve action
  • AI Reports: One-click Claude bilingual report generation
  • Response Protocol: G/Y/O/R reference + current actions
  • WebSocket consumer — updates every 2 seconds

06 · Alert System

Response
Protocol

The system maintains a five-state alert model for each zone. Levels are predicted by the SLM engine every tick and escalated automatically when thresholds are breached.

GREEN
Safe

Density < 3.5 p/m²
Routine monitoring only

YELLOW
Elevated

3.5 – 5.0 p/m²
Restrict entry, alert staff

ORANGE
High Risk

5.0 – 7.0 p/m²
Close entry, deploy dispersal

RED
Critical

≥ 7.0 p/m²
Full lockdown + NDRF

SUSPICIOUS
AI Anomaly

ML-detected pattern deviation — loitering, panic dispersal, unattended object

Alert Trigger Logic

# slm_engine.py — alert level prediction def predict_alert_level(snapshot: dict) -> str: density = snapshot["density"] # persons/m² inflow_rate = snapshot["inflow_rate"] # delta persons/min anomaly = snapshot["anomaly_score"] # 0.0 – 1.0 from ML model if anomaly > 0.75: return "SUSPICIOUS" # AI anomaly override elif density >= THRESHOLD_RED: return "RED" elif density >= THRESHOLD_ORANGE: return "ORANGE" elif density >= THRESHOLD_YELLOW: return "YELLOW" return "GREEN"
07 · Setup Guide

Getting
Running

1

Clone the project & run setup

The setup script installs all Python and Node.js dependencies, downloads the YOLOv8n model, initializes the SQLite database with seed data (50 cameras across 10 zones), and creates .env from the template.

bash setup.sh
2

Add your Anthropic API key

The AI incident report feature (bilingual English + Telugu) requires a Claude API key. Get one free at console.anthropic.com. The system runs in demo mode without it.

# .env ANTHROPIC_API_KEY=sk-ant-api03-your-key-here LLM_PROVIDER=anthropic LLM_MODEL=claude-sonnet-4-20250514
3

Start all services

Starts the FastAPI backend (port 8000) and React frontend (port 3000). The crowd simulation engine starts automatically and begins generating live data for all 10 zones.

bash start.sh
4

Or use Docker (full stack)

Docker Compose spins up 7 services: FastAPI, React, PostgreSQL 16, Redis 7, Kafka, Prometheus, and Grafana — production-equivalent environment in one command.

docker-compose up --build # Dashboard: http://localhost:3000 # API: http://localhost:8000 # API Docs: http://localhost:8000/docs # Grafana: http://localhost:3001
5

Test the AI: force an incident

Use the Python API to immediately trigger a RED alert on any ghat — useful for testing alert dispatch, SMS simulation, and Claude incident report generation.

from app.services.crowd_simulator import simulator # Immediately push Pushkar Ghat to RED simulator.force_incident("Pushkar Ghat 1") # Fetch all live zone snapshots snaps = simulator.get_all_snapshots() for zone, data in snaps.items(): print(zone, data["density"], data["level"])
